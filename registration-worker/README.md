# BrainBuilder Registration Worker

Python backend for registering adult mouse coronal histology sections to the
BrainGlobe `allen_mouse_25um` atlas (v1.2) and detecting fluorescent probe
tracks. The Swift app creates the project, displays review artifacts, and owns
the accept/reject decision; this worker performs the scientific image
processing and writes auditable JSON plus image/transform artifacts.

## Package stack

- **DeepSlice** estimates section plane position and angle and supplies
  QuickNII RAS anchoring coordinates. The worker explicitly flips/reorders
  those coordinates into BrainGlobe's ASR/AP-SI-RL array convention before
  sampling Allen CCF volumes.
- **BrainGlobe Atlas API** downloads and reads the versioned Allen CCFv3
  reference, annotation volume, and structure hierarchy.
- **SimpleITK** performs physical-coordinate, atlas-to-slice affine
  registration using Mattes mutual information and writes `.tfm` transforms.
- **scikit-image** and **scikit-learn** provide tissue segmentation, overlap QC,
  probe-track morphology, robust line fitting, and crosstalk suppression.
- **NumPy**, **SciPy**, **Pillow**, and **tifffile** handle array processing,
  oblique atlas sampling, and artifact I/O.

Python 3.11 is required. Install the locked environment with
[uv](https://docs.astral.sh/uv/):

```sh
uv sync --project registration-worker --python 3.11
```

The first atlas or pose command may download the BrainGlobe atlas and DeepSlice
model weights. Verify the runtime and atlas installation with:

```sh
uv run --project registration-worker python registration-worker/brainbuilder_worker.py doctor
```

## Workflow

The desktop app runs these commands automatically. For a CLI workflow, start
with the `RegistrationProject` JSON generated by the app:

```sh
# Validate unique section rasters and calibration; write masks and project.json.
uv run --project registration-worker python registration-worker/brainbuilder_worker.py prepare \
  --project exports/registration-worker/input-project.json \
  --out exports/registration-worker

# Estimate AP/angle pose with DeepSlice and write poses.json.
uv run --project registration-worker python registration-worker/brainbuilder_worker.py estimate-pose \
  --project exports/registration-worker/project.json \
  --out exports/registration-worker

# Register every section and write registered-project.json.
uv run --project registration-worker python registration-worker/brainbuilder_worker.py register-project \
  --project exports/registration-worker/poses.json \
  --stage affine \
  --out exports/registration-worker

# A single section can be retried independently.
uv run --project registration-worker python registration-worker/brainbuilder_worker.py register-slice \
  --project exports/registration-worker/poses.json \
  --slice-id XY01-montage-0 \
  --stage affine \
  --out exports/registration-worker
```

Review the generated atlas overlay, borders, checkerboard, difference image,
QC values, candidate overlays, rejected/unassigned points, and slice acceptance
in the app while Brain3D plan/ROI context remains hidden. Build or edit the
deterministic blind 3D partition before locking it:

```sh
uv run --project registration-worker python registration-worker/brainbuilder_worker.py review-blind-tracks \
  --project exports/registration-worker/accepted-project.json \
  --out exports/registration-worker/blind-review
```

Only after blind review is locked may the separate `review-brain3d` command reveal
planned shanks and ROI summaries. Every observed and planned item still requires an
explicit manual disposition. Export the reviewed project only after those gates:

```sh
uv run --project registration-worker python registration-worker/brainbuilder_worker.py export-atlas \
  --project exports/registration-worker/accepted-project.json \
  --out exports/atlas-registration
```

## Outputs and reliability contract

- A pose estimate is an initialization and review input, not an accepted atlas
  registration.
- Affine registration is quantitative only when a finite, invertible
  atlas-to-slice transform exists on disk in physical micrometre coordinates.
- Low tissue-mask IoU, degraded overlap, or suspicious atlas coverage marks a
  section for review instead of silently accepting it.
- Atlas export requires every section to be explicitly accepted and to have a
  usable affine transform plus annotation and boundary rasters. The export is
  self-contained: it copies source/structural/probe images, masks, transforms,
  atlas labels, boundaries, available review images, DeepSlice predictions, and
  a portable atlas ontology into the destination. Paths recorded by
  `atlas-export.json`, transform chains, and `accepted-project.json` are relative
  to the export root; SHA-256 provenance covers inputs, atlas assets, and every
  exported artifact.
- When a dedicated probe-fluorescence channel is present, each slice can retain up
  to 32 stable 2D RANSAC candidates plus rejected and unassigned points. Candidate
  detections are never silently accepted. Deterministic iterative 3D RANSAC then
  partitions accepted atlas points into at most 128 undirected finite A/B supports;
  every support needs at least three points across two accepted sections and each
  source point can belong to at most one support.
- Manual split, merge, and reassignment are represented by the exact schema-1 blind
  review state and deterministic-PCA schema-2 `probe-tracks.json` receipt. Seeds,
  source membership, reviewed-set digest, fit digest, RMSE, support length, point
  count, section count, and leave-one-section-out sensitivity are retained.
- Brain3D handoffs, ROI definitions, planned coordinates, shank counts, planned
  angles, colony receipts, and match dispositions are excluded from registration,
  2D candidate detection, and blind reconstruction inputs. Their presence or
  replacement must not change blind output digests.
- `atlas-export.json` schema 2 carries a closed-world file/hash manifest,
  `probe-tracks.json`, post-lock `brain3d-review.json`, prior receipt, and blind-stage
  digests. Observed supports are retrospective evidence only and are never treated
  as Neuropixels sites, entry/tip coordinates, navigation geometry, accuracy, or a
  safety/clearance result.
- A missing probe channel produces `noTrack`; the structural channel is never
  substituted as fake probe evidence.
- Spline/deformable registration remains review-gated. The worker returns a
  blocked result for `--stage spline` instead of fabricating a deformation
  field.

Every command emits a typed result envelope. Exit status is `0` for success,
`2` for a recoverable blocked condition (invalid input or unmet review gate),
and `1` for an execution failure. Use `--result-json PATH` with any command to
persist that envelope for automation.
